# PDF 压缩器

在**尽量不损失画质**的前提下减小 PDF 文件体积的 Windows 桌面工具。
纯本机运行，**完全离线，不启动服务器、不联网，文件不会离开当前电脑**。

---

## 一、使用方法（无需安装）

1. 双击 **`PDFCompressor.exe`**（位于项目根目录，下载后即可直接运行）
2. **拖入**（或点击「添加文件」上传）PDF 后，程序会**立即自动生成帕累托前沿图**
3. 用滑杆选择「画质优先 ← → 体积优先」（或点击高画质 / 均衡 / 最小体积快捷按钮）
4. 点击「开始压缩」，完成后双击列表中的文件可打开结果

> 适用系统：Windows 10 / 11 及以上版本的 64 位系统，无需安装 Python 或任何运行时。

## 二、压缩方式

程序对**每张位图**执行**多目标优化**：联合搜索「分辨率 × 编码器 × 质量」，计算
「体积」与「清晰度（PSNR + 对比度）」两个目标，在**该图的帕累托前沿**（非支配筛选，
并施加对比度下限）上按「前沿位置 position」选点。
无固定 DPI、无固定质量/压缩比，完全数据驱动。

> **术语口径（重要）**：单图层面的帕累托前沿是**真正的**非支配解集（已审计：前沿
> 「体积↑、清晰度↑」双调性成立，未被抽稀）。而界面上那条 **44 点曲线**是各张图在
> **同一个 position** 上选点后的**等索引聚合**——它是一个单调、可复现、可解释的
> 「画质-体积权衡族」，但按严格的数学定义**不是文档级帕累托前沿**：文档级最优要求
> 各图的边际替代率 dPSNR/dSize 相等（KKT 等边际条件），实测离散度达 1.6~4.0×，
> 13 个等索引点中有 11 个可被 λ-拉格朗日扫描方案支配。详见
> `tests/reports/pareto_audit_report.md`。本项目刻意保留等索引聚合，因为它保证
> 「滑杆位置 ↔ 输出文件」严格一一对应（44 点零误差），且各图观感一致。

界面提供两种选择方式：

- **滑杆（画质优先 ← → 体积优先）**：直接选择帕累托前沿上的任意点；滑杆方向与
  position 严格一一对应——**最左端「画质优先」= position 1.0（清晰度最高），
  最右端「体积优先」= position 0.0（体积最小）**；
- **三档快捷按钮**：高画质 / 均衡 / 最小体积——均为帕累托前沿上标定好的点。

三个档位对应的前沿位置 position（0=最小体积，1=最高画质/源文件）：

| 档位 | position | 说明 |
| --- | --- | --- |
| 高画质 | 0.7 | 偏画质，文字视觉无损 |
| 均衡 | 0.4 | 清晰度与体积兼顾 |
| 最小体积 | 0.05 | 偏体积，在保证清晰可读前提下尽量压缩 |

帕累托前沿图以**体积为横轴（MB，线性刻度，带网格线与确切刻度）、清晰度（PSNR）为纵轴
（固定 20~100 dB）**，共 **44 个前沿个体**（文档级等索引聚合曲线，口径见上文说明），
并单独标注「源文件」的体积。
**每个点都是一次真实压缩的结果**：前沿分析对 44 个位置逐个执行与「开始压缩」完全相同的
真实压缩，点的体积直接取自该次压缩产物——因此图上/轴上显示的体积与用户最终拿到文件的
真实体积**严格相等（误差恒为 0）**。点按前沿位置 position 等间距采样，故体积在横轴上
**并非**均匀分布（真实压缩曲线本就不是直线）。
图表支持**滚轮缩放、拖动平移、点击散点选点**，并与滑杆双向联动。

### 清晰可读与正确性保证

1. **清晰可读下限**：帕累托前沿上的每个点都必须满足 PSNR 下限与**对比度保持率下限**
   （灰度标准差保持 ≥ 70%），杜绝「压过头导致文字发灰不可读」。
2. **输出自校验**：压缩完成后内置 `verify_compression` 对产物做结构与内容双重校验
   （页数一致、每张位图可解码、PSNR/对比度达标），确保输出 PDF 正确。
3. **体积不回弹**：若压缩后文件反而变大，自动保留原文件。

> 编码仅使用 JPEG（有损）与 PNG 无损两种**通用格式**，保证在任何 PDF 阅读器中正常显示。
> （JPEG 2000 虽压缩率更高，但在部分阅读器中无法渲染，已因兼容性弃用。）

## 三、实测结果（66MB 扫描书 test_book.pdf，168 页）

| 档位 | 体积 | 减小 | 校验 | 最差 PSNR | 平均 PSNR |
| --- | --- | --- | --- | --- | --- |
| 高画质（pos 0.70） | 53.91 MB | 18.39% | ✓ 通过 | 36.2 dB | 53.9 dB |
| 均衡（pos 0.40） | 44.59 MB | 32.52% | ✓ 通过 | 31.8 dB | 50.9 dB |
| 最小体积（pos 0.05） | 17.52 MB | 73.48% | ✓ 通过 | 28.4 dB | 40.6 dB |

> 表中数值为当前引擎（Python 3.13 / Pillow 12.3）对三个预设档**真实压缩**的实测结果；
> 44 个前沿点的逐点验证（页面显示体积 vs 真实体积）**全部零误差**，见
> `tests/reports/frontier_44_report.md` 与 `TEST_REPORT.md`。

### 处理速度（66 MB / 168 页扫描书，打包后 exe 实测）

| 环节 | 耗时 |
| --- | --- |
| 拖入文件后生成帕累托前沿图（规划 + 44 点真实压缩） | 约 36 s |
| 点击「开始压缩」产出最终 PDF | 约 0.2 s（复用已完成的规划） |

引擎按位图并行规划（进程池，进程数 = `CPU 核数-1`，下限 2、上限 16），且规划结果
只取决于文件字节、与档位/滑杆无关，分析一次即可被压缩复用。进程池不可用时自动降级为
线程、再降级为串行，三级结果完全一致。可用 `PDFC_WORKERS` 覆盖进程数、
`PDFC_DISABLE_MP=1` 强制单进程。详见 `tests/reports/optimization_2026-10-11.md`。

实测加速（66 MB 扫描书，进程池 16）：规划阶段 **230.24 s → 28.37 s（8.12×，减少 87.7%）**；
零退化回归实测 **26.81 s（8.59×，减少 88.4%）**。

## 四、目标体积上限（体积约束与验收）

在「可选项」中可填写 **目标体积上限（MB）**。设定了目标后，程序会保证：

1. 先按当前所选档位压缩；
2. 若产物仍超过目标，**自动逐级增强压缩强度**（高画质 → 均衡 → 最小体积 → 极限）重试，
   取满足约束的最小产物；
3. 压缩完成后**核对产物大小**：若达到目标，列表直接显示最终体积；
4. 若连极限档位都无法满足目标，程序会**弹出说明**，给出超限原因与进一步优化建议，
   绝不静默交付超限文件。

> 留空目标体积表示不限制，仅按所选档位压缩一次。

## 五、压缩原理（业界先进技术综合应用）

本工具在**本地离线**环境下，综合应用了当前业界主流的 PDF 压缩与优化技术：

1. **多目标优化（速率-失真）**：对每张位图生成多分辨率 × JPEG（多质量）× PNG 无损
   候选，计算体积与 PSNR 两项目标，在帕累托前沿上按「前沿位置 position」选点，自动得到最佳折中。
2. **多分辨率候选 + 前沿择优降采样**：为每张位图枚举缩放因子 {1.0, 0.6, 0.4}
   （LANCZOS 抗锯齿）× 质量网格的候选，由帕累托前沿按「体积-清晰度」目标自动决定
   是否降采样、降到多少——不是预设 DPI 门槛的硬裁剪，而是数据驱动的择优
   （清晰度参考分辨率约 150 DPI 阅读分辨率）。
3. **灰度智能识别**：彩色扫描件若内容本就是灰度，自动转单通道灰度，典型情况下
   体积可再减约 1/3~1/2 且视觉无损（实际幅度取决于页面内容与噪声）。
4. **文字/照片内容分类 + 自适应色度采样**：依据边缘强度区分文字图表与照片，
   文字图表强制 4:4:4 并设可读性下限，避免边缘渗色；照片改用 4:2:0 进一步压缩。
   （注：这是**分类驱动的色度采样选择**，不是 MRC——本项目不做前景/背景分层与掩膜。）
5. **对比度保持约束**：额外校验灰度标准差保持率，防止文字被洗淡。
6. **结构层无损优化**：对象流生成（Object Stream）、完全相同的重复位图去重、
   删除缩略图与未引用资源；矢量与内容流原样保留（`normalize_content=False`）。
   **不对已有的 Flate 数据流做二次重压缩**（`recompress_flate=False`）——
   否则会破坏本引擎精心构造的 PNG 行预测器流并导致体积反弹。
7. **矢量内容零损伤**：文字、线条、矢量图形全程不参与任何有损处理。

> 说明：JBIG2 是黑白扫描件的更优编码，但其主流编码器为 AGPL 许可，与本项目的
> 闭源商业分发要求冲突，故未引入；已有的 JBIG2/CCITT 图像会被原样保留。

## 六、从源码构建

```bash
cd programs
python -m pip install pikepdf pillow pyinstaller tkinterdnd2
python build.py
```

构建产物为项目根目录下的 `PDFCompressor.exe` 单文件。

### 无界面自检（验证打包产物）

```bash
PDFCompressor.exe --selftest <输入.pdf> <输出.pdf> [position]
```

完整走一遍「规划 → 前沿分析 → 真实压缩 → 输出自校验」，并把报告写入
`<输出>.report.txt`（正式版为窗口程序无控制台，故结果落盘而非打印）。
正常双击启动不会进入此分支。
